# KV Cache 知识体系大纲 v2

> 主线原则：
> 1. **一条纵向基准线**：Full Attention · Llama-3-8B · PP2×TP2 贯穿"是什么 → 怎么建 → 怎么用 → 全流程"；
> 2. **一条横向支线**：其他类型 / 场景只记"与基准的差异"；
> 3. **机制只讲一处**：五维（内容/空间/生命周期/时间线/场景）只作每章检查清单，不做目录。
>
> 每篇内容开头声明所属格子（如 `A2`）；跨格内容只留链接，不复制。

---

## 0. 共同语言（地基，1 篇讲完）

- 0.1 为什么需要 KV Cache：自回归重算 O(n²) → 时间换空间
- 0.2 为什么分页：连续分配的浪费与碎片 → PagedAttention（虚拟内存思路）
- 0.3 块模型四要素：`block_size`（块容量）/ `page_size_bytes`（块字节）/ `num_blocks`（池容量）/ `block_table`（翻译器）
- 0.4 两条铁律：
  - 调度只认 block_id，kernel 只认张量行号；
  - `block_id == 张量行号`（逻辑↔物理唯一桥梁）。

**完成标准**：新人能复述"一条序列如何切块、如何经 block_table 落到物理页"。

## A. 类型体系（横向：有哪些）

- A1 三大家族 + spec 继承树：FullAttention / MLA / Mamba(GDN)，两大继承支与根 Spec 对比
- A2 每家族三件事：存什么、`page_size_bytes` 公式、物理 shape（换算示例：Llama-3-8B / DeepSeek-V3 / Qwen3.5）
- A3 格式变体（改字节与布局）：量化（FP8/INT8/INT4/NVFP4）、Diff-KV、HND/NHD stride
- A4 语义变体（布局不变、只改驻留策略）：SWA / chunked / sink / cross / RSWA / encoder-only
- A5 层间 merge 与 KVCacheGroupSpec 分组（为 E1 混合模型埋伏笔）

配图：`kvcache_type` / `kvcache_of_attention` / `kv_cache_mla` / `kv_cache_gdn`
**完成标准**：给任意模型，能算出每层块内容、`page_size_bytes`、物理 shape。

## B. 启动阶段：KV Cache 申请过程（纵向时间线①）

场景锚点：full attention（llama-3-8b pp2tp2）服务启动

- B1 编排总链一图：model config → spec 提取 merge → 分组 → KVCacheConfig → 张量 → 管理层装配
- B2 算规格：各层 `get_kv_cache_spec` → merge → 分组（group_size）
- B3 测预算：profile run → 可用显存 → watermark → `num_blocks`
- B4 物化：KVCacheTensor 订货单 → int8 底座 → reshape/permute 零拷贝 view → bind 给层
- B5 装配管理层：五层架构 KVCacheManager → Coordinator → SingleType → BlockPool → 物理张量（一层一句职责）
- B6 验收：画出 pp2tp2 每卡层分布、张量 shape、页落点

配图：`kvcache_fullattn_init` / `kv_cache_layout`
**完成标准**：给任意部署（pp×tp、单/混合模型），能画出每张卡的层分布、张量形状、块落点。

## C. 运行阶段：block_ids 索引使用（纵向时间线②）

- C1 BlockPool 数据结构三件套：KVCacheBlock（ref_cnt/缓存标志）/ FreeKVCacheBlockQueue / BlockHash + BlockHashToBlockMap
- C2 核心操作与不变量：分配 / touch / 释放（逆序、ref_cnt→0 回收）/ 驱逐 / CoW
- C3 前缀缓存：hash 计算 → 命中判定 → 满块写回（幂等、block_table append-only）→ 驱逐顺序
- C4 block_ids 流转：Engine 记账 → Scheduler 填入 SchedulerOutput 广播 → Worker 本地解释
- C5 写路径：新 token → `slot = block_id × block_size + offset` → `slot_mapping` → kernel
- C6 读路径：`get_block_ids` → `kv_caches[layer][:, block_ids]`（Full/MLA/Mamba 三族统一索引心智）

配图：`kvcache_fullattn_runtime`（多 group 版 `kv_cache_multi_group_blockid` 由 E1 引用）
**完成标准**：任一操作能说出块状态迁移、执行组件、保证的不变量。

## D. 一条请求的端到端 KV Cache 生命周期（收束章，串珠成链）

- D1 示例请求 + 总时序图
- D2 准入与调度：WAITING → RUNNING 门控（full_sequence_must_fit / watermark）
- D3 prefill 首步：`get_computed_blocks` 前缀查找
- D4 `allocate_slots` 三阶段：空间检查 → 前缀处理 → 新块分配
- D5 执行：prefill 写入 → chunked prefill → decode 追加（引用 C5/C6）
- D6 收尾：释放 / 抢占重算 / finish（块回收路径归 C2）
