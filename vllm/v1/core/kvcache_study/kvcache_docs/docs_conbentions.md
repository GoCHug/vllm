# KVCache 学习文档 · 写作约定

> 适用范围：`kvcache_docs/` 下所有分篇（`npu_hybrid/`、`npu_attn/`、`npu_mla/`、`gpu_attn/`、`0_kvcache/`、`1_logic_manager/`）。
> 用途：集中沉淀文档写作习惯（编号、结构、术语、表格、行尾等），新约定直接追加到对应小节或文末；正文不再重复解释这些规则。
> 现状：以下编号约定已在 `npu_hybrid/1_start_init.md` 全篇落地。

## 1. 四套记号总表

| 记号 | 层级 | 作用域 | 可否跨节引用 | 示例 |
|---|---|---|---|---|
| `S0`–`S5` | 全局阶段 | 整篇文档 | 可以 | `S3 做编排` |
| `3a`–`3e`、`4a`–`4d` | 章节内子步骤 | 单节（前缀 = 章节号） | 可以（`§3.3b`） | `3b 分组` |
| `(1)`–`(5)` | 函数 / 算法内部执行顺序 | 单个函数 | 不可以 | `(1) 分桶` |
| `①②③` | 普通并列列举 | 单段 | 不可以 | `分支①：开缓存…` |

一句话记忆：**`S` = 阶段，`3a` = 节内子步，`(1)` = 函数内步骤，`①` = 纯罗列**。

## 2. `S0`–`S5`：启动期六阶段

| 记号 | 阶段 | 执行位置 |
|---|---|---|
| `S0` | 配置期页对齐（page_size 统一） | API server（config 期） |
| `S1` | 算规格（各层产出 `KVCacheSpec`） | worker（经 RPC） |
| `S2` | 测预算（profile 量可用显存） | worker（经 RPC） |
| `S3` | 做编排（合并 → 分组 → 校验 → 生成 → 对齐） | EngineCore，平台无关 |
| `S4` | 落张量 + 编译预热 | worker（经 RPC） |
| `S5` | 建逻辑管理器 | EngineCore，平台无关 |

写法约定：

- 节标题：`### 3.1 S1 · 算规格：各层产出 KVCacheSpec`
- 正文首次出现：`S1 算规格`
- 区间引用：`S1–S4`；并列引用：`S1/S2/S4`
- 调用链内：`└─ S3 做编排  get_kv_cache_configs(...)`

禁止写法：

- `第 ① 步`、`①②③④⑤` 表示阶段（圈号不再承担阶段语义）
- `第一步 / 第二步`（与 `(1)` 视觉混淆）

## 3. `3a`–`3e` / `4a`–`4d`：章节内子步骤

规则：

1. **前缀数字 = 所属章节号**：§3.3 用 `3a`…`3e`，§3.4 用 `4a`…`4d`。
2. **编号取自上游依据**（函数 docstring 的编号条目 / 源码自然顺序），不自创。
3. 小节标题一律用四级标题：`#### 3b 分组：按层比例生成 KV cache group（`get_kv_cache_groups()`）`，与上级 `### 3.3` 形成层级；不用整行加粗代替标题。
4. 交叉引用：`§3.3b`、`见 3d`。
5. 字母必须连续、不跳号；增删子步时**同步更新三处**——该节映射表、调用链、正文引用。

## 4. `(1)`–`(5)`：函数内执行顺序

适用对象：单个函数体或单个算法的逐步说明（如切组的五步、预算校验的三动作、选档的两个条件）。

- 代码注释：`num_groups = cdiv(len(layers), group_size)   # (4) 1 与 3`
- 正文条目：`- **(1) 分桶**：key 是整个 spec 对象…`
- **只在本函数内有效**，不可跨节引用 `(3)`；需要跨节时升级为章节子步（`3c`）。

## 5. `①②③`：仅并列列举

保留给**并列关系**：原因、分支、条件、候选，不表示先后顺序。

- 分支：`├─ 分支①：开缓存 且 mamba_cache_mode=align → …`
- 理由：`① ssm 状态视图要求单段连续；② V 段语义被双池 API 固化；③ 两族同构使块级操作统一`

禁止用圈号表示任何"第几步"。

## 6. 与既有其它编号的共存

| 记号 | 含义 | 处理方式 |
|---|---|---|
| `§2.3`、`§3.3b` | 章节 / 子步引用 | 保留 |
| `第 1–5 层` | 逻辑管理器的装配层级（§4） | 保留；不与 `S` 混用 |
| `docstring 第 3 步` | 上游函数 docstring 的原编号 | 保留；必须带 "docstring" 前缀 |
| `[P0]`–`[P5]` | 进程标签（API server / EngineCore / worker） | 保留 |
| `√` / `※` | 调用链中"已展开小节" / "旁支或前置检查" | 保留 |
| `4a`–`4d` | §3.4 内部子步 | 适用第 3 节规则 |

## 7. 新增或修订文档时的检查清单

1. 圈号只出现在并列列举：`rg -n "[①②③④⑤]" <file>`，逐条确认。
2. 旧的阶段写法已清零：`rg -n "第 ?[①②③④⑤] ?步"`，应为 0。
3. 阶段标题都带 `S` 编号：`rg -n "^### 3\.[0-9] S[0-9]" <file>`。
4. `3x` / `4x` 名称在映射表、调用链、正文三处完全一致。
5. 代码围栏成对（三反引号数量为偶数）、行尾统一 CRLF。
6. **跨篇复用**：同一阶段在不同分篇用同一 `S` 编号；平台差异只改正文，不改编号。

## 8. 迁移示例

旧写法（三套圈号互相打架）：

```text
### 3.3 第 ③ 步 · 做编排
└─ ③ 做编排  get_kv_cache_configs(...)
├─ 3b 分组
- **① 分桶**：…
- **② 组大小**：…
```

新写法（四套记号各就各位）：

```text
### 3.3 S3 · 做编排
└─ S3 做编排  get_kv_cache_configs(...)
├─ 3b 分组
- **(1) 分桶**：…
- **(2) 组大小**：…
```

## 9. 其它写作习惯（持续补充）

| 习惯 | 做法 |
|---|---|
| 源码引用 | 代码块首行标出处：`# kv_cache_utils.py:1991-2003（节选）` |
| 实测值 | 每个关键数字给来源口径，如"本仓库 NPU 实测 `num_blocks ≈ 6003`" |
| 结论排版 | 能用表格就不用长段落；表格后紧跟 `>` 引注补充前提或边界 |
| 术语首次出现 | 写全中文 + 英文/代码符号（如"层名 `layer_name`"），后文统一用简称 |
| 平台差异 | 只改正文描述，不改阶段编号与章节结构 |
| 行尾 | 统一 CRLF；代码围栏成对 |
