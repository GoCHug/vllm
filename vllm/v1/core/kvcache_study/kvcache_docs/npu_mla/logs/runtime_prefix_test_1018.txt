## 数字闭环（token 级账本）

- Prometheus：vllm:prefix_cache_queries_total = 2925 = 970×3 + 15（冒烟 prompt 15 tokens）
                                       vllm:prefix_cache_hits_total   = 1792 = 896 × 2（warm2/warm3 各命中）
- 970 token prompt → 满块 7 个（7×128=896）入哈希表；第 8 块 74 token 未满不入；最后 1 token logits 必重算不可命中
  → warm 请求单次命中恰为 896 tokens
- 实验二 prompt 975 前 896 与前序完全相同 → 再命中 896：
  总 queries 2925+975=3900，总 hits 1792+896=2688，hit rate = 2688/3900 = 68.9%（与日志第二时刻一致）
- 第一时刻 61.3% = 1792/2925（日志与 metrics 双向印证）

## 结论

1. MLA latent + rope 为逐 token 因果序列 → 链式哈希前缀缓存照常工作（在线证据：61.3%/68.9% 命中率 + 精确 token 账）
2. 命中粒度与主线一致：仅满块（128 token）入表；未满尾块与最后一个 token 永不命中
3. 与 GDN 路线（enable_prefix_caching=False）形成直接分野实证
