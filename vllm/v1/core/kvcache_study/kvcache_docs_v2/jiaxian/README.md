**核心主张一句话**：KV Cache 管理是推理引擎的"显存操作系统"——`Scheduler` 只认一个门面，门面沿"分发→策略→账本"把工作分下去，每个 `block_id` 经一纸契约映射到另一台进程的仓库行号；NPU 的全部特殊性只在装配期流露，且整套机制可验到比特级。

> **v2 修订说明**（2026-10-18，用户评审意见）：v1"三侧五层"叙事两套坐标交叉（侧=启动角色、层=委托链），coordinator/门面被拔高成"层"导致读者高估其机制厚度，且静态结构被三章节重复扫描——v2 弃用该名目，改为**源码直译对象叙事（门面/分发/策略/账本/仓库/契约）+ 三个正交维度各讲一次**（空间维/装配维/运行维）。详见 0_outline.md §一。
